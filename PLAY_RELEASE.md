# Мандашня — релиз в Google Play (финальный чек-лист)

Этот документ описывает, что уже сделано в сборке и как выпустить игру в Google Play
через **TWA (Trusted Web Activity)** на базе этого PWA.

---

## 1. Что входит в сборку

**Рендер / графика**
- Настоящий 3D-движок на **WebGL** (`engine3d.js`) — свой мини-рендерер (меши, текстуры, освещение, буфер глубины, alpha-blend, проекция).
- Процедурные текстуры высокого качества (`textures3d.js`): дерево, металл, грани кубика, свечения.
- Полностью 3D-поле, кубик, зоны, дорожки, бонусы и фишки (`board3d.js`). Старый 2D-canvas-рендер отключён.
- Единая современная дизайн-система (`theme.css`): насыщённые градиенты, стекло (glassmorphism), крупные кнопки.

**Экраны**
- Меню, начало игры, настройки, профиль, онлайн, магазин, экран победы — переоформлены в одном премиум-стиле.
- Кубик в игре — 3D-объект по центру поля; тап по нему = бросок (подсказка-пульс на своём ходу).
- Убран технический «клаттер» для рядового игрока (крипто-пруф честности кубика скрыт).

**Совместимость**
- Установка как PWA, офлайн-режим через service worker (`sw.js`, кеш `mandashnya-v17`).
- Портретная ориентация, safe-area, тёмная тема статус-бара.

## 2. Безопасность (сделано)

- **CSP**: добавлен `Content-Security-Policy` в `index.html` (ограничены источники скриптов/стилей/соединений; разрешены только домены Firebase/Google).
- **XSS**: весь пользовательский текст (ник, сообщения чата, аватары) выводится через экранирование `netEsc()` (textContent → innerHTML). HTML в никах/чате рендерится как текст.
- **Firebase Realtime Database rules** (`database.rules.json`):
  - чтение/запись только для аутентифицированных пользователей;
  - профиль может править только его владелец (`auth.uid === $uid`);
  - длины ника (≤20), аватара (≤8), сообщений (≤200) валидируются на сервере;
  - в чатах `uid` сообщения обязан совпадать с `auth.uid` (нельзя писать от чужого имени);
  - запрет на любые неописанные корневые узлы (`$other: read/write false`).
- **Публичный web API-ключ Firebase** — это нормально и не является секретом (доступ ограничивают именно правила БД + домены). Ограничьте ключ в Google Cloud Console по «HTTP referrers» и включённым API.

### Обязательно перед публикацией
1. В консоли Firebase → Realtime Database → Rules — вставьте содержимое `database.rules.json` и опубликуйте.
2. Firebase → Authentication → Settings → **Authorized domains**: добавьте ваш домен хостинга и домен TWA.
3. Google Cloud Console → Credentials → ограничьте web API-ключ (referrers + только нужные API).

## 3. Хостинг PWA

Выложите содержимое папки на HTTPS-хостинг (Firebase Hosting / Netlify / Vercel / свой сервер).
Проверьте, что доступны по HTTPS: `index.html`, `styles.css`, `theme.css`, `engine3d.js`,
`textures3d.js`, `board3d.js`, `game.js`, `firebase-config.js`, `manifest.json`, `sw.js`,
иконки и `assets/*`.

Проверьте PWA в Chrome DevTools → Lighthouse (Installable, PWA, Best Practices).

## 4. Упаковка в APK/AAB через Bubblewrap (TWA)

```bash
npm i -g @bubblewrap/cli
bubblewrap init --manifest https://ВАШ-ДОМЕН/manifest.json
# packageId например: com.mandashnya.game
bubblewrap build
```

Bubblewrap создаст подписанный `app-release-signed.apk` и `app-release-bundle.aab`
(последний загружается в Play Console).

### Digital Asset Links (обязательно для TWA без адресной строки)
1. Возьмите SHA-256 отпечаток ключа подписи:
   - если используете **Play App Signing** — отпечаток в Play Console → Release → Setup → App signing.
   - локальный ключ: `keytool -list -v -keystore ваш.keystore`.
2. Впишите `package_name` и `sha256_cert_fingerprints` в `.well-known/assetlinks.json`
   (шаблон уже лежит в проекте) и выложите его по адресу
   `https://ВАШ-ДОМЕН/.well-known/assetlinks.json`.
3. Проверка: https://developers.google.com/digital-asset-links/tools/generator

## 5. Google Play Console — чек-лист

- [ ] Создать приложение, заполнить Store listing (название, описание, короткое описание).
- [ ] Графика: иконка 512×512, feature graphic 1024×500, минимум 2 скриншота (телефон).
- [ ] Категория: Игры → Настольные. Контент-рейтинг (анкета IARC).
- [ ] Политика конфиденциальности (URL) — обязательна (есть онлайн/аккаунты).
- [ ] Data safety: укажите сбор ника/аватара/статистики и аутентификацию.
- [ ] Target API level — актуальный (Bubblewrap ставит корректный по умолчанию).
- [ ] Загрузить `.aab`, пройти внутреннее тестирование, затем production.
- [ ] Проверить, что при запуске TWA нет адресной строки (assetlinks корректны).

---

## 6. Быстрая проверка перед сборкой

- Игра запускается офлайн (после первого визита) — работает service worker.
- Меню, поле, кубик, магазин, профиль, настройки — единый современный стиль.
- 3D-поле и кубик рендерятся (WebGL), без ошибок в консоли.
- Онлайн: вход, лобби, чат, рейтинг — работают на HTTPS-домене.

Версия кеша: `mandashnya-v17`. При каждом обновлении статики поднимайте номер кеша в `sw.js`.
